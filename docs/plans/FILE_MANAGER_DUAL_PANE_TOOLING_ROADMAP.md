# 内置文件管理器双栏与工程工具补全路线图

> 状态：后续推进计划  
> 范围：主页面“内置文件管理”入口下的双栏文件管理器、压缩包/APK/Dex/ARSC 工程工具、批量任务和可维护性拆分。  
> 目的：记录当前缺口、优先级、验收标准，避免后续继续开发时遗漏。

## 1. 当前已具备

当前版本已经具备以下基础能力：

- 主页面右上角可进入内置文件管理器。
- 管理模式默认打开外部存储根目录。
- Compose 双栏绘制已恢复，并接近 MT 风格高密度布局。
- 左右窗格具备独立路径、独立选择集、右窗格后退/前进/上级和刷新。
- 左右窗格支持复制、移动、新建、重命名、删除。
- 顶部“菜单 / 更多”已接入焦点窗格位置和操作菜单。
- 底栏动作会按焦点窗格作用到左侧或右侧。
- 文件点击可打开工具菜单。
- APK 信息、APK 签名事实扫描、Dex 事实扫描、ARSC 事实扫描、压缩包浏览、解压、属性、复制路径等入口已可达。
- 工具菜单对未实现项会明确显示规划面板，不假装能力已完成。

## 2. 主要缺口

### 2.1 双栏文件操作

当前复制/移动可用，但还缺完整文件管理器级别的操作体验：

- 复制/移动前确认目标窗格和目标路径。
- 冲突策略 UI：覆盖、跳过、保留两者、全部应用。
- 冲突列表预览。
- 操作失败详情面板。
- 操作完成后打开目标位置。
- 操作取消后的部分结果报告。
- 可选撤销入口，至少对同目录移动/重命名提供保守撤销。

### 2.2 压缩包能力

当前已有浏览和解压入口，但还不够完整：

- 多选压缩为 zip。
- 当前目录打包为 zip。
- 解压到左窗格 / 右窗格 / 指定授权目录。
- 压缩包内条目复制到另一窗格。
- 压缩包内文本/图片/APK 资源预览。
- 压缩包内搜索。
- APK 内 `AndroidManifest.xml`、`classes.dex`、`resources.arsc` 快捷入口。

### 2.3 APK / Dex / ARSC 工程工具

当前是事实扫描，不是完整逆向工具链。后续缺口：

- APK 快捷分析页，集中展示 Manifest、Dex、ARSC、签名、native so、证书条目。
- AndroidManifest 二进制 AXML 解码。
- AXML 属性树浏览和格式化文本导出。
- Dex 类/方法/字段/字符串列表浏览。
- Dex 字符串搜索。
- Dex 导出 smali。
- 接入 jadx 或等价反编译后端，导出 Java 预览。
- resources.arsc 包表浏览、资源 ID 查询、字符串池查看。
- apktool 解包。
- apktool 回编译。
- zipalign / apksigner 签名与对齐。
- APK 工具输出目录管理和清理。

### 2.4 文件预览与编辑联动

当前文件预览可达，但双栏语境下还缺联动：

- 文本文件从工具菜单直接进入编辑模式。
- 保存后刷新来源窗格。
- 右窗格打开预览后返回时保持右窗格焦点。
- 压缩包条目预览缓存清理策略。
- 图片、文本、二进制预览入口在工具菜单中进一步细分。
- 大文件预览前展示大小和风险提示。

### 2.5 搜索能力

当前搜索主要是当前目录列表过滤。后续需要：

- 递归文件名搜索。
- 文件内容搜索。
- 搜索范围选择：当前窗格、左右窗格、当前目录及子目录、压缩包内。
- 搜索条件：类型、大小、修改时间、隐藏文件。
- 搜索结果可打开所在目录、复制、移动、删除。
- APK/Dex 字符串搜索与跳转。

### 2.6 权限、Root、SAF 边界

后续需要继续打磨：

- 不可写目录操作前明确提示原因。
- SAF 写入失败后的恢复建议。
- Root 路径复制/删除/重命名能力策略。
- Android 11+ 外部存储受限场景提示。
- Root 高危操作必须二次确认，默认保守关闭。

### 2.7 任务系统

当前已有任务进度状态，但还不是完整任务系统：

- 统一任务队列。
- 后台执行与取消。
- 当前文件名、速度、剩余时间。
- 失败报告复制/保存。
- 多任务历史。
- 搜索、压缩、解压、复制、移动、删除统一事件模型。

### 2.8 架构拆分

`LocalFileManagerFragment` 仍在继续变重。后续需要拆分：

- `DualPaneFileManagerController`
- `FileToolActionDispatcher`
- `FileManagerTransferTaskController`
- `PaneLocationNavigator`
- `FileManagerDialogCoordinator`
- `ArchiveToolingController`
- `ApkToolingController`

## 3. 推荐推进顺序

### 阶段 A：把现有双栏体验补稳

目标：让双栏文件管理器成为日常可用状态。

任务：

- [x] 补复制/移动目标确认。第一版已接入双栏跨栏复制/移动前确认目标窗格、目标路径和数量。
- [x] 补冲突策略 UI。第一版支持整批选择保留两者、覆盖、冲突停止。
- 补失败详情面板。
- [x] 补双栏“解压到左/右窗格”。第一版已接入焦点窗格当前目录和对侧窗格目标目录，支持批量压缩包解压和失败报告。
- [x] 补多选压缩为 zip。第一版已接入焦点窗格选中项压缩，输出到当前窗格目录，并复用批处理失败报告。
- 补顶部/底部按钮的可用性状态和禁用原因。

验收：

- 左右窗格常用复制/移动/删除/重命名不需要退回单栏。
- 冲突不再只靠默认策略悄悄处理。
- 失败原因可查看、可复制。
- 编译通过：`./gradlew :app:compileDebugKotlin`。

### 阶段 B：文件工具分发拆出 Fragment

目标：降低 Fragment 负担，为工程工具继续扩展铺路。

任务：

- 新增 `FileToolActionDispatcher`。
- 将 APK 信息、签名、Dex、ARSC、属性、复制路径、压缩包浏览、解压分发迁出 Fragment。
- 新增 `FileToolActionContext`，包含窗格、当前路径、选中项、导航回调、复制路径回调等。
- 为工具分发补轻量单测或纯 Kotlin 测试。

验收：

- Fragment 不直接知道每个 `FileToolId` 的具体处理细节。
- 新增工具只改 registry 和 dispatcher。
- 原有工具入口不回退。

### 阶段 C：APK 快捷分析页

目标：把零散 APK 工具入口合并为一个实际可用的 APK 分析工作台。

任务：

- 新增 APK 分析面板。
- 展示基础信息、签名事实、Dex 摘要、ARSC 摘要、Manifest 条目、native so 架构。
- APK 分析页提供快捷按钮：浏览压缩包、查看 Dex、查看 ARSC、查看 Manifest、复制路径。
- 对大 APK 保持异步扫描和进度状态。

验收：

- 点击 APK 后可以从一个面板进入主要工程分析入口。
- APK 签名/Dex/ARSC 信息不再散落在多个孤立面板。
- 不执行危险安装或未知来源动作。

### 阶段 D：AXML / Dex / ARSC 深化

目标：从事实扫描进入可浏览的逆向辅助工具。

任务：

- AXML 解码为文本树。
- Dex 字符串/类/方法列表浏览。
- Dex 字符串搜索。
- ARSC 字符串池和资源 ID 查询。
- 从 APK 内快捷打开 `AndroidManifest.xml` / `classes.dex` / `resources.arsc`。

验收：

- APK 内常见逆向入口可不离开应用完成初步查看。
- 大文件扫描可取消。
- 解析失败展示明确错误而不是崩溃。

### 阶段 E：外部逆向工具链接入

目标：接入真正反编译/回编译能力。

任务：

- 调研 jadx/apktool 在 Android 端或 bundled runtime 中的可行路径。
- 确定工具输出目录。
- jadx 反编译 Java 预览。
- apktool 解包。
- apktool 回编译。
- zipalign / apksigner 签名。
- 输出清理和任务日志。

验收：

- 工具链不存在时 UI 明确提示安装/不可用，而不是显示假入口。
- 工具链存在时能完成至少一个最小闭环：APK -> 解包/反编译 -> 查看输出。
- 回编译/签名必须有明确输出路径和错误日志。

### 阶段 F：搜索和任务系统统一

目标：把递归搜索和长任务纳入统一任务模型。

任务：

- 新增任务队列或任务 runner。
- 搜索作为可取消任务。
- 复制/移动/压缩/解压统一进度事件。
- 失败报告可复制/保存。
- 任务历史可选记录。

验收：

- 长任务均可取消。
- 失败报告统一。
- UI 不依赖零散 Toast 表达复杂结果。

- 多选压缩为 zip。
- 解压到左/右窗格。
- `FileToolActionDispatcher` 抽出。

### P1：完成后继续

- AXML 解码。
- Dex 字符串/类/方法浏览。
- ARSC 字符串池和资源 ID 查询。
- 搜索当前目录及子目录。
- 文件预览保存后刷新来源窗格。

### P2：重工具链

- jadx 反编译。
- apktool 解包/回编译。
- zipalign / apksigner。
- 任务历史。
- Root 写入类高级能力。

## 5. 工程约束

- 不复制 MT 管理器或其他闭源/不兼容许可证实现代码。
- Root 写入、删除、chmod/chown、remount 等高危能力默认保守关闭。
- 工具链不可用时必须明确展示不可用原因。
- 大文件和长任务必须可取消或至少可中断 UI 等待。
- 每轮功能推进后至少运行 `./gradlew :app:compileDebugKotlin`。
- 涉及资源、Manifest、权限或构建配置时最低验证应为 `./gradlew assembleDebug`。

## 6. 当前建议下一刀

建议下一轮从 P0 中选择一个纵向切片：

1. `FileToolActionDispatcher` 抽出，降低 Fragment 复杂度。
2. 同时补“解压到左/右窗格”和“多选压缩为 zip”。
3. 随后补复制/移动冲突策略 UI。

这样能先把现有可用能力稳定下来，再进入 jadx/apktool 这种更重的外部工具链。
