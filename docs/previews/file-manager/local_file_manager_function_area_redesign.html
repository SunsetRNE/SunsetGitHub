🛠 方案 B · 强悍工程文件管理器

功能区 UI 重绘设计稿

目标不是“按钮换个样式”，而是把已经接通的文件操作能力组织成可理解、可预期、可高频使用的工程操作面板： 底部常驻工具区负责高频入口，选中态工具区负责批量操作，底部 Sheet 负责完整能力分组，弹窗负责风险确认、目标选择、冲突处理和进度反馈。

能力分层常用操作在底栏；危险/高级操作进入 Sheet；长任务统一进度。
目标优先复制、移动、解压都先明确目标目录，再执行，不再靠猜。
工程感授权目录、双栏、压缩、解压、转换、失败报告都是一等能力。

颜色语义

主要动作：新建、复制、打开、确认
产物动作：压缩、解压、转换、导出
目录/授权/目标选择等上下文操作
危险动作：删除、覆盖、冲突继续
工程增强：双栏、压缩包、批处理

三、动效与控件规范

动效以“帮助理解状态变化”为目标，不做花哨转场；布局需能直接映射到 XML View + Material Components。

底栏切换普通底栏 ↔ 选中态底栏使用 180ms fade + slideUp，减少突然跳变。
Sheet 展开底部 Sheet 从底部 220ms decelerate 弹出，背景 scrim 渐入。
进度更新进度条使用 120ms linear progress 动画，文字同步更新 completed/total。
危险确认删除、冲突继续、覆盖策略使用红色主按钮，弹窗不可被误触发。

四、落地拆分建议

当前 Fragment 已经承载大量弹窗与操作逻辑。UI 重绘落地时建议顺手拆分职责，避免后续继续膨胀。

建议新增 XML / 组件

  • view_file_manager_action_bar.xml：普通底部功能区。
  • view_file_manager_selection_bar.xml：选中态批量操作区。
  • bottom_sheet_file_manager_actions.xml：完整操作 Sheet。
  • bottom_sheet_file_manager_target_picker.xml：复制/移动/解压目标选择。
  • dialog_file_operation_progress.xml：统一进度弹窗。
  • dialog_file_operation_failures.xml：失败详情与报告复制。

建议新增 Kotlin 边界

  • LocalFileManagerActionRenderer：只负责渲染功能区状态。
  • LocalFileManagerDialogs：集中管理确认、失败、属性、进度弹窗。
  • FileOperationTargetPicker：统一复制/移动/解压目标选择。
  • FileOperationProgressController：统一长任务进度与后台化扩展。
  • FileManagerOperationUiModel：把按钮文案、启用态、危险态从 Fragment 中抽出。

功能区按钮优先级

新建授权双栏搜索更多 复制到移动到压缩解压到转TXT删除

状态覆盖

  • 无选择：显示普通功能区与目录导航。
  • 有选择：显示批量操作区，隐藏普通底栏。
  • 双栏开启：目标窗格 Chip 与传输入口高亮。
  • 长任务中：显示不可取消/可后台的进度层。
  • 失败/冲突：必须提供明细与复制报告。
