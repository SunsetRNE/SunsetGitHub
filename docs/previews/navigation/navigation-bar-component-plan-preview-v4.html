Spec v4 · Runtime + Debuggability

差的不是更多变体，而是运行时闭环

v3 讲了变体系统，但还不够，因为它仍然偏静态。真正能落地的组件规格，需要回答：输入如何变成像素、状态如何迁移、token 从哪里来、动画如何衔接、问题如何调试、第一刀怎么切。

v4 把导航栏设计成一条运行时管线：Context -> Policy -> Variant -> RenderPlan -> Measure/Layout -> Draw/Animate -> Insets/Events/Debug。

一、运行时管线

这一层是前几版缺掉的东西。它让组件从“结构合理”变成“行为可解释”。

1. Contextdestination、arguments、auth、theme、window、ime、scroll、capability
2. Policy页面是否允许导航栏、菜单类型、强制隐藏、仓库上下文
3. Variantplacement、material、density、surface、behavior、fallback
4. RenderPlan尺寸、圆角、颜色、stroke、shadow、menu items、animation
5. Commitmeasure/layout/draw、发布 inset、派发事件、记录 debug snapshot
关键：View 不应该临时推理业务，Host 不应该临时设置像素。中间必须有 RenderPlan，作为“状态到像素”的可测试边界。

三、Token 系统：不要把尺寸和颜色散在 renderer

玻璃和变体会失败，常常不是因为架构，而是因为每个 renderer 自己写 margin、alpha、stroke、height。必须集中成 token。

Token 类别字段来源变体影响
Sizeheight、compactHeight、railWidth、floatingMargin、hitSlopdimens + window metricsPlacement、Density、IME
ShapecornerRadius、dockCornerRadius、strokeWidthstyle tokenMaterial、Density
Colorsurface、surfaceAlt、stroke、itemSelected、itemMutedtheme attrsSurface、HighContrast、Dark
GlasstintAlpha、blurRadius、saturation、highlightAlphamaterial preset + capabilityMaterial、Capability
Motionduration、easing、interruptModemotion tokenBehavior、Accessibility reduce motion

四、状态机：避免动画和 inset 打架

悬浮、隐藏、键盘、切页会互相打断。需要状态机定义谁能到谁，动画如何中断。

Detached
组件未 attach。不能 render glass，不能发布 inset。
Attached.Hidden
组件 attach 但不可见。inset = 0，menu 可预构建但不提交视觉。
Attached.Visible.Docked
底部占位导航。内容避让 = bar height + system navigation consideration。
Attached.Visible.Floating
overlay 悬浮导航。内容可绘制到底部，但滚动区要有 touch/read padding。
Transitioning
任意可见性或 placement 变化进入过渡态。过渡完成后一次性发布最终 debug snapshot。
规则：inset 发布应跟随目标态，而不是每一帧动画态，否则列表底部会跟着抖。

五、调试能力：否则玻璃问题很难定位

六、页面级契约：Fragment 如何配合

导航栏独立后，Fragment 不应该知道它怎么画，但需要声明自己对底部 overlay 的偏好。

页面契约含义例子
AllowsNavigationBar页面允许导航栏显示Home、Dashboard、仓库详情
ForcesNavigationBarHidden页面强制隐藏导航栏登录子流程、全屏预览、沉浸编辑
PrefersCompactWhenImeVisible键盘出现时压缩而不是隐藏搜索页、轻量表单
ConsumesBottomInset页面自己处理 inset自带 RecyclerView inset 管理的复杂页面

七、最小纵向切片

别第一轮铺满整个系统。最小切片应该证明“运行时管线成立”。

1

模型层

State、Variant、RenderPlan、Insets、DebugInfo。

2

Planner 层

Docked Solid、Floating FakeGlass、Hidden 三种 plan 可单测。

3

View 层

AppNavigationBarLayout 接收 RenderPlan，不直接推理业务。

4

Host 接入

MainActivity 只收集 context，调用 pipeline，转发事件。

5

验证

主导航页 + 仓库页 + 未钉选分区 + 浮动开关 + 隐藏页。

八、v4 之后才算完整的原因

完整标准：方案必须同时包含组件边界、变体系统、运行时管线、RenderPlan、token、状态机、调试能力和最小切片。v1-v3 分别补了方向、物理边界、变体扩展；v4 补的是“它实际怎么跑”。
反模式：如果新增一个变体需要改 Activity、Fragment、Host、Renderer 里的多个 when，这个组件系统就失败了。
