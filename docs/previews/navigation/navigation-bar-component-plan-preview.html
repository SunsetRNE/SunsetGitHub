独立悬浮导航栏组件方案

目标不是简单移动代码，而是把底部导航栏抽成一个具有独立物理边界的渲染组件，后续可以彻底实现悬浮导航、统一底色渲染、玻璃材质、内容避让和动画过渡。

当前实现已经拆出了 HostController、Renderer、MenuBinder 和 DestinationRegistry，但导航栏仍依赖 Activity 布局里的 BottomNavigationView、divider、container，以及对 Fragment 根视图的外部 padding 修补。本方案将这些能力收敛到一个组件内部。

目标效果：导航栏作为独立 overlay 组件，自管玻璃、圆角、阴影、点击区和内容避让。
问题 1

底色来源不统一

Fragment、Activity 背景、BottomNavigationView 背景分别绘制，悬浮时容易出现底色和内容不一致。

问题 2

玻璃没有物理边界

玻璃需要 backdrop、tint、stroke、blur、clip、shadow 协同，目前这些职责散在布局和 renderer 里。

问题 3

内容避让是外部修补

当前通过 navHostView.post 给 Fragment 根视图补 padding，切页时可能产生一帧错位或不一致。

一、目标组件边界

新增一个物理组件 AppNavigationBarLayout，外部只向它输入状态、接收事件。组件内部继续可以使用 BottomNavigationView，但这个实现细节不再暴露给 MainActivity。

建议把导航栏物理组件放在新的子包中，与目的地策略、偏好存储、仓库分区业务分开。

三、状态与事件设计

组件应该围绕状态渲染，而不是由外部直接操作 BottomNavigationView。这样后续切换玻璃、悬浮、Docked、Rail 都只影响 renderer。

AppNavigationBarState.kt 状态
data class AppNavigationBarState(
    val visibility: AppNavigationBarVisibility,
    val placement: AppNavigationBarPlacement,
    val material: AppNavigationBarMaterial,
    val menu: AppNavigationBarMenu,
    val selectedItemId: Int?,
    val contentAvoidance: ContentAvoidance
)

enum class AppNavigationBarVisibility {
    Visible,
    Hidden
}

enum class AppNavigationBarPlacement {
    Docked,
    Floating
}

sealed interface AppNavigationBarMaterial {
    data object Solid : AppNavigationBarMaterial
    data object FakeGlass : AppNavigationBarMaterial
    data class Glass(
        val blurRadiusDp: Float,
        val tintAlpha: Float,
        val strokeAlpha: Float
    ) : AppNavigationBarMaterial
}
AppNavigationBarEvent.kt 事件
sealed interface AppNavigationBarEvent {
    data class MainDestinationSelected(
        @IdRes val destinationId: Int
    ) : AppNavigationBarEvent

    data class RepositorySectionSelected(
        val section: RepositorySection
    ) : AppNavigationBarEvent

    data object RepositoryMoreSelected : AppNavigationBarEvent
}

sealed interface AppNavigationBarMenu {
    data object Main : AppNavigationBarMenu

    data class RepositorySections(
        val sections: List<RepositorySection>,
        val selectedSection: RepositorySection
    ) : AppNavigationBarMenu
}

五、玻璃渲染路线

不要第一步就做复杂真模糊。建议先建立 material 管线，再逐步替换 backdrop renderer。

阶段实现收益风险
阶段 A：统一底色 Solid / SurfaceColor，统一使用主题 surface、canvas、stroke。 先解决 UI 和底色内容渲染不一致。 没有真玻璃，但稳定。
阶段 B：假玻璃 半透明 tint + stroke + elevation + 圆角裁剪 + backdrop-filter 风格近似。 视觉接近玻璃，兼容 minSdk 28。 不是背后内容真实模糊。
阶段 C：RenderEffect 玻璃 Android 12+ 使用 RenderEffect 或 snapshot layer。 可获得更真实的模糊材质。 性能、滚动同步、截图频率需要控制。
阶段 D：高级 BackdropRenderer 独立 renderer 管理 snapshot、失效、降级策略。 玻璃能力可插拔，不影响导航业务。 实现复杂，建议最后做。
建议：第一轮只实现 Solid + FakeGlass。先把物理组件、状态、内容避让和菜单事件稳定下来，真模糊作为后续 renderer 替换。

六、内容避让策略

导航栏组件不应该直接修改 Fragment 根 View，而是发布自己需要的 bottom inset。宿主或统一 applier 负责应用到 NavHost 当前内容。

AppNavigationBarInsets.kt 组件输出
data class AppNavigationBarInsets(
    val bottomContentPaddingPx: Int,
    val bottomGesturePaddingPx: Int,
    val isOverlayingContent: Boolean
)

enum class ContentAvoidance {
    None,
    ReserveDockedSpace,
    ReserveFloatingTouchSpace
}
NavigationContentInsetApplier.kt 宿主应用
class NavigationContentInsetApplier(
    private val navHost: ViewGroup
) {
    fun apply(insets: AppNavigationBarInsets) {
        val contentRoot = navHost.getChildAt(0) ?: return
        if (contentRoot is ViewGroup) {
            contentRoot.clipToPadding = false
        }
        contentRoot.updatePadding(
            bottom = insets.bottomContentPaddingPx
        )
    }
}
关键点：Docked 模式可以保留完整底部空间；Floating 模式允许内容绘制到底部，但为滚动内容保留触摸和阅读空间；Hidden 模式清空避让。

七、仓库分区菜单优化

当前从 More 打开未钉选分区时，底栏菜单可能没有该分区，导致无法高亮。组件化时建议一并修复。

RepositoryNavigationMenuModelFactory.kt 临时显示当前分区
class RepositoryNavigationMenuModelFactory {
    fun create(
        shortcutSections: List<RepositorySection>,
        orderedSections: List<RepositorySection>,
        selectedSection: RepositorySection
    ): List<RepositorySection> {
        val shortcuts = orderedSections
            .filter { it in shortcutSections }
            .take(3)
            .toMutableList()

        val shouldExposeSelected =
            selectedSection != RepositorySection.Code &&
            selectedSection != RepositorySection.More &&
            selectedSection !in shortcuts

        if (shouldExposeSelected) {
            if (shortcuts.size >= 3) shortcuts.removeLast()
            shortcuts += selectedSection
        }

        return listOf(RepositorySection.Code) + shortcuts + RepositorySection.More
    }
}

八、迁移步骤

1

新增状态和事件模型

添加 AppNavigationBarState、AppNavigationBarEvent、AppNavigationBarMenu，不改变现有 UI。

2

新增 AppNavigationBarLayout

内部先复用 BottomNavigationView，迁入背景、margin、elevation、divider、clip 逻辑。

3

替换 activity_main.xml

用单个自定义组件替换 nav_view_container、nav_view_divider、nav_view。

4

HostController 改为状态输出

让 NavigationBarHostController / AppNavigationBarHost 只生成 state 和处理 event，不再直接操作 BottomNavigationView。

5

引入 ContentInsetApplier

组件发布 inset，宿主统一应用，移除 renderer 内部直接修改 NavHost 子 View 的逻辑。

6

实现 FakeGlass

先用半透明 surface、stroke、shadow、圆角裁剪解决视觉一致性，再预留 RenderEffectGlass。

7

补测试和交互验证

验证目的地规则、仓库分区菜单生成、未钉选分区高亮、Docked/Floating/Hidden inset。

九、验收标准

结构

MainActivity 变薄

MainActivity 不再知道 BottomNavigationView、divider、menu.clear、inflateMenu、clip/elevation/margin。

视觉

底色一致

Docked 和 Floating 模式下，导航栏背景、页面底色、Activity canvas 不再出现明显断层。

扩展

玻璃可替换

Solid、FakeGlass、RenderEffectGlass 可以通过 material renderer 切换，不改导航业务。

注意：不要第一轮就把真模糊、截图采样、滚动同步全部做完。先完成独立物理组件和假玻璃，确保现有导航功能无回退后，再进入真玻璃 renderer。
