三、设计细节

细节决策原因
视觉语言GitHub native 低饱和，不使用彩色 acrylic 作为主方案项目现有资源是 canvas/surface/border/accent 体系
默认态Docked Solid 保留为 baseline用于等价迁移、低风险 fallback、高对比场景
悬浮态Floating Frosted 先落地，Glass 作为增强 material renderer先解决底色连续和组件边界，再做更重的玻璃
暗色态暗色玻璃单独 token，不能复用浅色 alpha暗色下透明和高光的视觉权重完全不同
未选中项使用 github_text_secondary，禁用使用 github_text_muted避免夜间黑色图标/文字不可读
仓库临时分区从 More 打开的未钉选分区临时占用一个快捷槽保证当前分区可见、可高亮
紧凑态Compact 使用 icon only，作为键盘/低高度场景防止 label 裁切和触摸区域不足

四、资源层建议

资源 / Token当前状态建议动作
bg_bottom_nav_docked.xmlsolid = github_surface保留，映射为 Docked Solid material
bg_bottom_nav_floating.xmlgithub_floating_nav_background + border + radius保留，映射为 Floating Frosted 基础 material
nav_item_tint.xmldefault/disabled 使用 black改为 token 化：checked=github_accent，default=github_text_secondary，disabled=github_text_muted
values-night/nav_item_tint.xml建议新增确保夜间未选中项不再是黑色
dark glass token尚未存在在组件 renderer 内定义，不急于新增 drawable
RenderEffect glass尚未实现作为后续增强，第一轮不用真 blur
优先级最高：先修复 nav item tint 的夜间可读性，再谈玻璃材质，否则暗色导航栏会一直不可信。

五、后续跟进计划

阶段目标交付物验证
1资源修正修复 nav_item_tint，新增 night tint暗色 Docked 底栏未选中项清晰可读
2组件壳AppNavigationBarLayout，内部先复用 BottomNavigationViewDocked Solid 与当前行为一致
3RenderPlanState -> RenderPlan -> commit 管线主导航和仓库导航切换不回退
4Floating Frosted迁移现有 floating 背景为组件 material底色连续，内容不被遮挡
5Repository Temp未钉选分区临时入栏规则从 More 打开 Pull Requests 能高亮
6Dark Glass Candidate暗色专用 glass token真机截图确认不过暗
7正式化文档ADR + issue 切片 + 测试清单后续维护者能按阶段接手
最小成功标准：MainActivity 变薄，导航栏成为独立组件；现有 Docked/Floating 行为不回退；暗色可读；仓库临时分区可高亮；玻璃效果作为可选 material，而不是散落在 Activity 和 Fragment 里。
