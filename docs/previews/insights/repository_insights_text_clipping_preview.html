页面 2：根因判断

优先怀疑点集中在 RepositoryInsightsFragment 动态创建的 TextView，而不是 XML 顶层滚动容器。

原因 A

简介被 maxLines 限制

仓库简介使用 createBodyText(description).apply { maxLines = 3 }，长简介一定会被截断。这个属于主动摘要策略，但当前没有省略号提示，容易像“被挡住”。

原因 B

正文默认 selectable

createBodyText 默认 setTextIsSelectable(true)。在动态卡片、圆角背景和紧凑布局中，可选择文本层可能导致测量/绘制边界异常，出现底部视觉裁剪。

原因 C

卡片布局比较紧

提示卡片图标 + 文本横向排列，文本宽度被压缩，长英文、长版本名会制造更多换行，对高度测量更敏感。

// 当前高风险点：通用正文默认可选择
private fun createBodyText(textValue: String): TextView = TextView(requireContext()).apply {
    text = textValue
    setTextAppearance(R.style.TextAppearance_SunsetGitHub_Material_Body)
    setTextColor(ContextCompat.getColor(requireContext(), R.color.github_text_secondary))
    setTextIsSelectable(true)
}

页面 3：最小修复方案

不大改页面结构，只把“可选择文本”变成按场景开启，并给被限制的简介加明确省略行为。

推荐先做

正文选择能力参数化

把 createBodyText 增加 selectable 参数，默认 false。只有确实需要复制的 debug/原文区域再显式 true。

private fun createBodyText(
    textValue: String,
    selectable: Boolean = false
): TextView = TextView(requireContext()).apply {
    text = textValue
    setTextAppearance(R.style.TextAppearance_SunsetGitHub_Material_Body)
    setTextColor(ContextCompat.getColor(requireContext(), R.color.github_text_secondary))
    setTextIsSelectable(selectable)
}
推荐同步做

简介截断显式化

如果简介仍保留 3 行摘要，就加 ellipsize = END；如果希望完整展示，就移除 maxLines。

addView(createBodyText(description).apply {
    maxLines = 3
    ellipsize = TextUtils.TruncateAt.END
})

影响范围

  • 改动集中在 RepositoryInsightsFragment，风险较低。
  • 不会影响 GitHub API、缓存、导航和 XML 顶层结构。
  • 可复制文本能力会从“所有正文默认可复制”变成“需要复制的地方显式开启”。

页面 4：增强方案

如果想顺手提高这个页面的观感，可以把提示卡片和指标卡片的文本策略拆得更清楚。

1

区分摘要文本与完整文本

简介类内容可使用 3 行摘要 + “查看更多”；提示/安全探测类内容默认完整展示，避免误解为数据丢失。

2

给长 token 留更稳定的换行策略

版本号、Release 名、英文长句容易撑布局，可考虑 breakStrategy、hyphenationFrequency 或给 TextView 设置更友好的换行策略。

3

卡片增加最小高度而不是固定高度

保持视觉统一，但让内容自然撑开。所有提示卡都用 WRAP_CONTENT，高度不要硬编码。

4

只在详情/Debug 处开启 selectable

普通移动端卡片以阅读优先，复制能力放到详情页或长按菜单，减少 TextView 选择层副作用。

页面 5：验证清单

修复后建议用这几类内容做回归，确保既不裁文字，也不破坏页面节奏。

视觉验证

页面样例

  • 中文长句：安全探测、Dependabot、Code scanning 多项提示。
  • 英文长句：仓库简介含长英文描述。
  • 超长版本名：Release 标题包含连字符、下划线、中文混排。
  • 小屏设备：宽度 360dp 左右。
代码验证

检查点

  • 提示卡片没有 maxLines。
  • 简介如果保留 maxLines，必须有 ellipsize。
  • createBodyText 默认 selectable=false。
  • 需要复制的文本显式传 selectable=true。

建议落地顺序

先做最小修复并构建验证；如果截图问题消失，再考虑“查看更多”和长文本换行策略。这样可以把根因验证和视觉增强分开，避免一次改动过大。
