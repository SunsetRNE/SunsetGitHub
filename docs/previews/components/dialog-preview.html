初步调整建议

基于当前预览和项目弹窗用法整理。

建议统一的组件边界

  • 危险确认 / 覆盖 / 删除：优先迁移到 CompactBlackDialog。
  • 单选、多选、表单编辑：继续使用默认 MaterialAlertDialogBuilder，但统一主题样式。
  • 复杂业务说明：保留 Fork 同步这类自定义 View 弹窗。

视觉一致性问题

  • 默认弹窗圆角和按钮弱于自绘弹窗，品牌感不一致。
  • Compact 系列黑色标题区非常突出，不宜用于普通信息提示。
  • 文件来源选择器缺少顶部黑色头部，但更轻量，适合选择入口。

可落地改动方向

  • 抽一个统一 Dialog 入口，按场景选择默认 / compact / bottom sheet。
  • 给默认 MaterialAlertDialog 主题补齐圆角、按钮字体和 GitHub 边框感。
  • 后续可把冲突弹窗、删除文件弹窗优先改为 CompactBlackDialog。
结论：现有自绘弹窗已经有明确风格，最需要调整的不是单个组件外观，而是“哪些业务场景应该使用哪一种弹窗”。建议先不大改布局资源，先统一弹窗使用策略：默认弹窗负责普通选择/编辑，CompactBlackDialog 负责高风险确认，FileSourcePickerDialog 负责本地文件入口，BottomSheet 负责长列表和分区导航。
