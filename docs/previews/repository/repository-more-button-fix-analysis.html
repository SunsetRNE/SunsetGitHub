仓库“更多”弹窗与竖屏按钮缺失修复方案

针对 SunsetGitHub 仓库设置页中看不到仓库分区“更多”按钮的问题，梳理现状、根因，并给出比“让每个 Fragment 继承基类”更稳的集中式修复方案。

1. 结论摘要

“更多”弹窗本身在 RepositoryMoreSectionsBottomSheet.kt，按钮不是页面内的普通按钮，而是被动态加入到底部 BottomNavigationView 的仓库分区导航项。

竖屏截图中的 RepositorySettingsFragment 没有稳定渲染仓库分区底栏，因此看不到“更多”。更好的修复不是给每个设置页重复接入导航，而是把仓库分区导航收敛为 MainActivity 根据当前 destination 自动渲染 的单一职责。

推荐：Activity 集中式仓库分区导航 避免遗漏页面 规避 stale Fragment callback 需要小心与现有 Fragment 调用去重

2. 现状定位

  • 弹窗类：app/src/main/kotlin/com/Sunset/REN/GitHub/ui/repo/RepositoryMoreSectionsBottomSheet.kt
  • 分区枚举：RepositorySection.kt，其中 More 是最后一个分区。
  • 动态底栏入口：MainActivity.showRepositorySectionNavigation()
  • 截图页：RepositorySettingsFragment : Fragment()

3. 根因

当前有两套触发路径：一些仓库分区页继承 RepositorySectionFragment 并主动调用 renderRepositorySectionNavigation()，仓库详情页也自己调用。可是设置页与设置子页是普通 Fragment，没有主动刷新仓库分区底栏。

因此进入设置页时，底栏是否存在依赖前一个页面残留状态；当竖屏显示面积有限时，用户就会明显感知为“没有更多按钮”。

4. 当前调用链

RepositorySection定义 Code / Issues / Settings / More 等分区
Fragment 手动调用部分页面调用 renderRepositorySectionNavigation()
MainActivityshowRepositorySectionNavigation() 动态重建 navView.menu
点击 More触发 showRepositoryMoreSectionsSheet()
BottomSheetRepositoryMoreSectionsBottomSheet 展示分区列表
问题点：“是否显示仓库分区底栏”的责任分散在各个 Fragment。只要某个仓库页漏调，底栏就可能不稳定；如果保留旧 Fragment callback，还可能出现 stale callback 风险。

5. 备选方案对比

方案 做法 优点 缺点 / 风险 推荐度
A. 让设置页继承 RepositorySectionFragment 把 RepositorySettingsFragment 与子设置页逐个改成基类，并实现 owner/repo/selectedSection。 局部直观，改动小。 页面多时容易漏；每个页面都要维护重复代码；仍然是分散式责任。 60%
B. 在设置页手动调用 Activity 的导航刷新 保留 Fragment，在 onViewCreated/onResume 手动调用宿主接口。 侵入更小。 还是会遗漏；子页也要处理；不能根治职责分散。 50%
C. Activity 根据 NavController destination 自动渲染 MainActivity 在 destination changed 时，如果当前是仓库相关 destination 且参数包含 owner/repo，就统一渲染仓库分区底栏。 单一职责；不依赖每个 Fragment 是否记得调用；设置页、子页天然覆盖；点击 More 由 Activity 处理，避免 stale Fragment callback。 需要处理与现有 Fragment 主动调用的去重；需要确保所有仓库页参数一致。 90%
D. 把“更多”改成顶栏菜单 在 top app bar 加统一更多入口。 按钮更显眼，不依赖底栏空间。 改变交互模型；与底部分区导航重复；需要重新梳理菜单权限和页面语义。 40%

6. 推荐方案：Activity 统一拥有仓库分区底栏

设计决策：仓库分区导航属于应用壳层导航，不应该由每个内容 Fragment 自己负责。建议让 MainActivity 根据当前目的地和参数统一决定是否显示仓库分区底栏、显示哪些分区、当前选中哪个分区、点击后导航到哪里。

核心行为

  • 在 NavController.addOnDestinationChangedListener 中集中判断。
  • 如果不是仓库相关页面：调用 clearRepositorySectionNavigation()，恢复主导航。
  • 如果是仓库相关页面且有 owner/repo 参数：调用 refreshRepositorySectionNavigationFromPreferences()。
  • 当前选中分区通过现有 sectionForDestination(destination.id) 计算。
  • “更多”点击由 MainActivity.showRepositoryMoreSectionsSheet() 处理。

伪代码

navController.addOnDestinationChangedListener { _, destination, arguments ->
    val isRepoPage = isRepositoryRelatedDestination(destination.id)
    val hasRepoArgs = hasRepositoryIdentity(arguments)

    if (isRepoPage && hasRepoArgs) {
        ensureRepositorySectionNavigation(destination.id, arguments)
    } else if (isRepositorySectionNavigationActive) {
        clearRepositorySectionNavigation()
    }

    updateMainNavigationSelectionIfNeeded(destination.id)
    applyNavigationBarForDestination(destination.id, arguments)
    applyRepositoryTitleForDestination(destination.id, arguments)
    invalidateOptionsMenu()
}
private fun ensureRepositorySectionNavigation(destinationId: Int, arguments: Bundle?) {
    val repositoryFullName = repositoryFullNameFrom(arguments)
    val shortcutSections = repositoryNavigationPreferencesRepository
        .getRepositoryShortcutSections(repositoryFullName)
    val orderedShortcutSections = repositoryNavigationPreferencesRepository
        .getRepositorySectionOrder(repositoryFullName)
        .filter { section -> section in shortcutSections }
    val navigationSections = listOf(RepositorySection.Code) + orderedShortcutSections + RepositorySection.More
    val selectedSection = sectionForDestination(destinationId)

    showRepositorySectionNavigation(
        sections = navigationSections,
        selectedSection = selectedSection,
        onSectionSelected = { section ->
            if (section == RepositorySection.More) showRepositoryMoreSectionsSheet()
            else navigateToRepositorySection(section)
        }
    )
}

7. 兼容现有代码的落地顺序

  1. 先在 MainActivity 新增 ensureRepositorySectionNavigation(...) 和 hasRepositoryIdentity(...)。
  2. 在 destination changed listener 中调用它，覆盖所有仓库相关页面。
  3. 保留现有 Fragment 里的 renderRepositorySectionNavigation()，依靠 showRepositorySectionNavigation() 的菜单 ID 比较去重，先降低风险。
  4. 验证稳定后，再逐步删除 Fragment 侧重复渲染逻辑，最终让 Activity 成为唯一入口。

8. 需要特别检查

  • 所有仓库页导航参数是否都有 RepositoryDetailFragment.ARG_OWNER 与 ARG_REPO。
  • 设置子页，例如 branch/collaborators/actions/danger zone/webhooks/rulesets/deploy keys 是否都在 isRepositoryRelatedDestination() 与 sectionForDestination() 中覆盖。
  • 点击 More 后，BottomSheet 的 host 应优先使用 Activity，不再依赖旧 Fragment 实例。
  • 横竖屏切换后，destination listener 是否能重新构建底栏。

9. 推荐验收用例

场景 预期
从仓库详情进入仓库设置页 底部仍显示仓库分区栏，最后一项为“更多”。
直接深链/恢复到仓库设置页 不依赖前一个页面，也能显示“更多”。
进入分支、协作者、Actions 设置等子页 底栏选中 Settings，仍可点“更多”切换到其它仓库分区。
点击“更多”并固定/取消固定分区 底栏快捷分区立即刷新；弹窗不会因 stale Fragment callback 崩溃。
离开仓库页回首页/仓库列表/设置 恢复主底部导航，不残留仓库分区栏。

10. 最终建议

如果只是快速修复截图页，可以让 RepositorySettingsFragment 继承 RepositorySectionFragment。但从维护性看，这会把“仓库分区导航”的责任继续散落到各个页面。

更好的方案是：由 MainActivity 作为应用壳层统一根据当前 Nav destination 渲染仓库分区底栏。这样所有仓库相关页，包括设置页和设置子页，都能自然拥有“更多”按钮；以后新增仓库页时，只需要补充 destination 映射，而不用记得在 Fragment 里手动调用导航渲染。
